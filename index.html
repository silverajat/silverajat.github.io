U2Trading engineRTL verified · board ordered

Crypto order-flow engine on my own Zynq-7020 board

Verilog that takes live exchange data over Ethernet, rebuilds the order book in hardware and computes trading signals. A PicoRV32 RISC-V core handles control, and a hardware risk gate can stop it.

  • Price-time matching engine: all 102,044 events of a 69-minute real stream identical to the C++ engine
  • Switching to a tick-ladder order book cut latency from 8.8 to 3.4 µs (p50) and 53.5 to 7.6 µs (p99)
  • Hardware timestamps line up with the pins to 10 ns; latency histograms on chip
  • Designed the 6-layer board with DDR3L to run it

Music-sync LED controller

U4WearableBuilt · in daily use

Lift tracker wearable

A Fitbit-sized wrist pod and an Android app that count gym reps while you lift, grade each rep's range of motion and end the set on their own.

  • 32 of 33 real sets counted exactly on the prototype, all within one rep; the Kotlin counter is checked against a Python reference model in CI
  • My own 4-layer board (nRF52840, LSM6DSV16X), 0.55 mm thinner than a Fitbit Air, charging on its charger, firmware updates over Bluetooth
  • Bring-up: debugged a board that killed its battery, a sealed pod with no reset button (added a watchdog) and a 25%-in-two-hours battery drain

TP1Approach

Model first, then RTL, then the board

  1. 01

    Reference model

    C++ or Python that does exactly what the hardware should, tested on its own first.

    C++ matching engine
  2. 02

    Replay real data

    cocotb feeds recorded data into the RTL: exchange feeds, gym sets, audio.

    69 min of market data
  3. 03

    Compare every value

    Any mismatch with the model fails the test.

    102,044 / 102,044 match
  4. 04

    My own board

    Schematic, layout, fab files, bring-up.

    5 boards, up to 6 layers

When something breaks on the bench, I write down why in the repo. The ledctl JTAG loader exists because the flash programmer didn't work.
